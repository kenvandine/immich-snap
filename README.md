# immich snap

A strictly confined snap of [Immich](https://immich.app) (self-hosted photo and
video management), translated from Umbrel's
[docker-compose.yml](https://github.com/getumbrel/umbrel-apps/blob/master/immich/docker-compose.yml)
using the `docker-compose-to-snap` skill. The whole stack — web/API server,
machine-learning service, PostgreSQL 18 + pgvector, Valkey — runs as snapd
daemons in one snap. No Docker involved.

## Architecture

| Compose service | In this snap |
|---|---|
| `app_proxy` (Umbrel glue) | Dropped; port 2283 exposed directly |
| `server` (immich-server v3.0.3 image) | Payload extracted from the pinned OCI image, runs on the image's node via `/usr/local` layout |
| `machine-learning` | venv extracted from the pinned OCI image to `/opt/venv` (layout) |
| `redis` (valkey 8) | `valkey-server` from the 26.04 archive, unix socket only, runs as `snap_daemon` |
| `postgres` (custom image w/ vector extensions) | `postgresql-18` + `postgresql-18-pgvector` from the archive, unix socket only, runs as `snap_daemon`, `DB_VECTOR_EXTENSION=pgvector` |

- Base: `core26` (the v3.0.3 images are Debian trixie / glibc 2.41 — too new
  for core24's glibc 2.39).
- Data: `/var/snap/immich/common` (uploads, DB cluster, model cache).
- Secrets (`DB_PASSWORD`, `JWT_SECRET`): generated by the install hook into
  `$SNAP_DATA/secrets`, replacing the compose file's hardcoded values.
- Config: `sudo snap set immich ports.http=2283 log-level=log machine-learning.enabled=true`
- `sudo immich.psql` opens a database shell.

## Build

```bash
snapcraft pack --verbose
sudo snap install ./immich_*.snap --dangerous
snap services immich
curl -fsS http://localhost:2283/api/server/ping   # expect {"res":"pong"}
```
